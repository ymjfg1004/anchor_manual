1.1. 구매거래처 정보

개요

자재·원재료·서비스를 공급받는 구매거래처(공급사)를 등록·관리하는 화면입니다. 여기서 등록한 거래처는 구매요청서·발주서·송장 등 후속 구매 업무에서 선택 대상으로 사용됩니다.

🧱 거래처는 ‘기본정보 + 거래조건(기본통화/결제조건/인도조건/평균리드타임) + 담당자/계좌정보’를 한 등록 팝업에서 모두 입력합니다. 결제조건·인도조건은 발주 시점에 그대로 끌어오므로 가급적 모두 설정합니다.

  • ② 그리드 — 등록된 거래처 한 행이 거래처 1건. 결제조건/인도조건/담당자명/신용등급 셀의 돋보기 아이콘으로 별도 선택 팝업을 열어 빠르게 변경할 수도 있습니다.

  • ⑬ 인도조건 / 평균리드타임 — 인코텀스 기반 인도조건과 발주 후 입고까지 평균 일수. 평균리드타임은 MRP 계산에 사용
  • ⑭ 전용품목 — 토글 ON 시 해당 거래처에만 발주 가능한 ‘전용품목’ 관리 메뉴 연동
  • ⑮ 거래등급 — 신용·실적 기반 거래등급 (해당없음/A/B/C 등)
  • ⑯ 담당자정보 / 계좌정보 탭 — [추가]로 담당자(이름/직위/연락처/이메일)와 송금 계좌 정보를 등록. 발주서·송장 메일 발송 시 이 담당자가 수신자로 기본 설정됩니다.

2.1. 구매요청서

개요

자재/원재료가 필요한 부서가 구매요청(Purchase Request, PR)을 등록하는 화면입니다. 구매요청서는 발주서(PO)의 원천 문서로, 여기서 등록한 품목·수량·납기가 발주의 기준이 됩니다.

🧱 구매요청서 1건은 ‘요청 헤더(요청번호/일자/공장/요청부서/요청자)’와 ‘여러 줄의 품목정보(품목/수량/창고/납기)’로 구성됩니다. 작성 후에는 결재상신을 통해 승인 절차를 거친 뒤 발주서로 전환됩니다.

화면 진입

좌측 사이드바 [구매관리] ▸ [구매요청(PR)] ▸ [구매요청서]

목록 화면

상단에는 구매요청서 헤더 목록, 하단의 ‘상세품목정보’ 영역에는 상단에서 선택한 요청서의 품목 라인들이 표시되는 2단 구조입니다.

구매요청서 목록 — 상단: 요청서 헤더 / 하단: 선택된 요청서의 품목 상세 / 우측에 결재상신 버튼

  • ① 기능 버튼 — [마감] / [등록] / [수정] / [삭제] / [복사] / [출력] / [다운로드] / [결재상신]
  • ② 요청서 그리드 — 한 행이 요청서 1건. 구매요청번호 / 구매요청일자 / 공장 / 요청납기일자 / 프로젝트 / 현장 / 요청부서 / 요청자 / 비고 / 구매요청상태 / 요청경로 / 최종작업자 / 작업일시
  • ③ 상세품목정보 — 상단 그리드에서 선택한 요청서의 품목 라인 목록. 품목코드 / 품목명 / 품목유형 / 규격 / 단위 / 구매요청수량 / 공장 / 창고 / 요청납기일자 / 비고 / 미발주수량 / 상태
  • ④ 결재상신 — 작성한 구매요청서를 전자결재로 올려 승인을 받는 버튼. 결재 완료된 요청서만 발주서 생성 후보가 됩니다.

🔄 상태 흐름 — [작성중] → [결재상신] → 결재 진행 중/완료 → 발주서 생성 시 [발주]/[미발주] 잔량 표시. 미발주수량이 0이 되면 해당 라인은 발주 완료.

구매요청서 생성 방식

구매요청서는 3가지 방식으로 만들 수 있습니다. 어떤 방식이든 결과물은 동일한 ‘구매요청서’ 한 건이며, 이후 결재상신·발주 전환은 같은 흐름입니다.

  • MRP 기반 자동 생성 — 주관부서: 생산관리팀. MRP 실행 시 자재 부족 분이 산출되면 구매요청서 초안이 자동 생성됩니다.
  • 안전재고 기반 자동 생성 — 주관부서: 창고관리팀. 품목별 안전재고수량 미만이 되면 일배치로 자동 생성됩니다. 실행 시각: 매일 새벽 2시.
  • 요청자 수기 생성 — 요청자가 본 화면에서 [등록] 버튼으로 헤더·라인을 직접 입력하고 필요 시 첨부도 등록합니다. (아래 ‘구매요청서 등록’ 참조)

안전재고 기반 자동 생성 — 설정 방법

품목 단위로 [기초정보] ▸ [품목정보] 화면의 ‘재고정보’ 탭에서 자동 구매요청 조건을 설정합니다.

품목정보 ▸ 재고정보 탭 — 안전재고수량 / 자동구매요청 / 재주문수량 설정

  • 안전재고수량 — 보유 재고가 이 수량 아래로 떨어지면 보충이 필요한 기준.
  • 자동구매요청 — 사용 선택 시 일배치 대상이 됩니다. 미사용이면 안전재고 미만이어도 자동 생성하지 않습니다.
  • 재주문수량 — 자동구매요청이 트리거됐을 때 생성되는 요청서의 요청수량. 즉 "안전재고 아래로 떨어지면 재주문수량만큼 요청".
  • 적정재고수량 — 참고용 보조 필드 (자동 생성 트리거에는 직접 사용되지 않음)

🕑 실행 흐름 — 매일 새벽 2시에 ‘자동구매요청 = 사용’인 품목을 스캔 → 현재고 < 안전재고수량인 품목에 대해 재주문수량만큼의 구매요청서 초안 자동 생성 → 창고관리팀이 검토·결재상신.

구매요청서 등록

상단 [등록] 버튼을 클릭하면 구매요청서 등록 팝업이 열립니다.

구매요청서 등록 팝업

  • ① 헤더 1행 — 구매요청번호(자동 채번) / 구매요청일자(오늘) / 요청납기일자(오늘) / 공장*. 공장은 발주처(자재가 들어올 공장)를 선택
  • ② 헤더 2행 — 프로젝트 / 현장 / 요청부서 / 요청자. 사용 안 하면 비워둬도 됩니다.
  • ③ 비고 — 요청서 전체에 대한 메모 (예: Case A — 정상 베이스 RM-A01 60EA × 1,000)
  • ④ 품목정보 — 요청 품목 라인을 등록하는 영역. [품목불러오기] 클릭 → 품목 조회 팝업에서 선택. 라인별 필수: 요청수량* / 공장* / 창고* / 요청납기일자*

[저장] → 요청서가 ‘작성중’ 상태로 목록에 추가됩니다.

구매요청서 수정

목록에서 요청서를 체크박스로 선택한 뒤 [수정] 버튼 클릭. 동일 폼이 데이터가 채워진 상태로 열립니다.

구매요청서 수정 — PR2605210001 (Case A) 데이터가 채워진 상태

  • 이미 발주서가 생성된 라인은 ‘미발주수량’이 줄어든 상태로 수정에 제약이 있을 수 있습니다.
  • 결재 진행 중/완료 상태의 요청서는 수정이 막힙니다. 정정이 필요하면 결재를 회수하거나 새 요청서를 등록하세요.

전자결재로 업무 승인

구매요청서는 작성 후 [결재상신] 버튼으로 전자결재 문서를 생성·상신합니다. 결재가 완료되어야 발주서 생성 단계로 넘어갈 수 있습니다.

3.1. 발주서(구매오더)

개요

승인된 구매요청서(PR)를 근거로 거래처에 보낼 발주서(Purchase Order, PO)를 만들고 송부·결재상신·발송까지 처리하는 화면입니다. 발주서가 만들어지면 ‘기발주 수량’이 늘고 PR의 ‘미발주 수량’이 줄어들며, 이후 입고(GR)·송장(IR) 단계의 기준 문서가 됩니다.

🛒 발주 흐름 — 구매요청서(PR) ▸ 발주서(PO) ▸ 물품입고(GR) ▸ 송장접수(IR). 본 화면에서는 PR을 끌어와서 PO를 만드는 ‘구매요청서 불러오기’ 흐름을 사용합니다.

화면 진입

좌측 사이드바 [구매관리] ▸ [구매오더(PO)] ▸ [발주서(구매오더)]

목록 화면

기본 조회 조건은 ‘발주일자 기준 당월 1일~오늘’입니다. 우상단 기간을 바꿔 다른 기간의 발주서도 조회할 수 있습니다.

발주서(구매오더) 목록 — 상단: 발주정보 / 하단: 선택 발주서의 상세품목정보

  • ① 기능 버튼 — [마감] / [구매요청서 불러오기] / [결재상신] / [복사] / [출력] / [다운로드] / [발송] / [발송내역]. 새 발주서는 보통 [구매요청서 불러오기]로 시작합니다.
  • ② 발주정보 그리드 — 한 행이 발주서 1건. 발주번호 / 발주일자 / 거래처 / 요청공장 / 납기일자 / 통화코드 / 적용환율 / 과세구분 / 결제조건 / 인도조건 / 프로젝트 / 현장 / 부서 / 사원
  • ③ 상세품목정보 — 상단에서 선택한 발주서의 품목 라인. 품목코드 / 품목명 / 품목유형 / 규격 / 단위 / 발주수량 / 단가 / 공급가 / 부가세 / 합계 / 공장 / 창고 / 입고번호

ℹ️ 조회 팁 — 매뉴얼 예시처럼 5월 전체를 보려면 우상단 기간을 ‘2026-05-01 ~ 2026-05-31’로 바꾸고 [조회] 클릭. ‘발주일자 / 납기일자’ 등으로 기준일을 바꿀 수도 있습니다.

1단계. 구매요청서 불러오기

상단 [구매요청서 불러오기] 버튼을 클릭하면 ‘구매요청기반 발주서 작성’ 팝업이 열립니다.

구매요청기반 발주서 작성 — 5/9 작성된 PR2605260001 선택, 발주수량 40/100 입력

  • ① 검색 조건 — 구매요청일자 / 요청부서 / 요청자로 후보를 좁힙니다. 기본은 본 메뉴 조회 기간을 따라옵니다.
  • ② 구매요청정보 — 발주 후보 PR 목록. 발주로 만들 PR 1건 또는 여러 건의 체크박스를 선택합니다. (예시: 5/9 자 PR2605260001 ‘[Case F] 추가매입’ 선택)

🔍 여기 조회되는 PR은 다음 두 조건을 모두 만족한 건만 보입니다.
① 결재 ‘승인 완료’ 상태 — 결재 진행 중·반려·회수 상태의 PR은 후보에서 제외됩니다.
② 발주 가능한 잔여(미발주수량 > 0)가 남아 있음 — 구매요청수량이 100% 발주된 PR은 더 이상 조회되지 않습니다.

  • ③ 품목별 발주수량 입력 — 위에서 선택한 PR의 품목 라인이 펼쳐집니다. 각 라인의 발주수량 셀에 발주할 수량을 직접 입력합니다. 미발주수량 = 발주수량으로 두는 게 일반적이고, 분할 발주가 필요하면 일부만 입력해 잔여를 남깁니다.
  • ④ [발주하기] — 발주수량을 채운 라인만 모아 발주서 등록 팝업으로 넘어갑니다. 발주수량이 비어 있으면 ‘발주수량을 입력해 주세요’ 알림이 뜹니다.

🔢 발주수량 의미 — 구매요청수량(요청한 총량) − 기발주수량(이미 발주된 양) = 미발주수량(남은 양). 발주수량은 미발주수량 이내로 입력해야 합니다. 잔여수량은 ‘미발주수량 − 발주수량’으로 자동 계산되어, 0이 되면 그 라인은 발주 완료.

2단계. 발주서 등록

‘구매요청기반 발주서 작성’에서 [발주하기]를 누르면 발주서 등록 팝업이 열립니다. PR 헤더·라인 정보가 자동으로 채워진 상태입니다.

발주서 등록 — PR2605260001 기반, 두 품목 라인 + 단가·공급가·부가세·합계 자동 계산

  • ① 발주번호 / 발행경로 — 발주번호는 ‘자동부여’로 저장 시 채번. 발행경로에는 구매요청서(PR2605260001) 처럼 원천 PR이 표시됩니다.
  • ② 발주일자* / 요청납기일자* / 요청공장 — 발주일자는 오늘로 채워지고, 요청납기일자·요청공장은 PR 값을 그대로 가져옵니다.
  • ③ 거래처 / 결제조건 / 인도조건 — 거래처는 돋보기로 직접 선택. 거래처를 선택하면 ‘거래처 기본 결제조건·인도조건’이 자동으로 채워집니다.
  • ④ 프로젝트 / 현장 / 부서 / 사원 — 비용 귀속을 위한 보조 정보. 필요 시 입력.
  • ⑤ 비고 — 발주서에 대한 자유 메모 (포장 조건, 운송 요청사항 등)
  • ⑥ 과세구분 / 외화거래 / 통화정보 — 기본값: 과세 / 부 / KRW (환율 1). 외화 발주면 ‘여’로 바꾸고 통화·환율 지정.
  • ⑦ 품목정보 그리드 — PR에서 가져온 라인. 품목코드 / 품목명 / 규격 / 발주수량* / 단가* / 공급가* / 부가세* / 합계* / 공장* / 창고* / 요청납기일자*. 단가는 거래처-품목 단가가 등록돼 있으면 자동, 없으면 직접 입력. 공급가·부가세·합계는 발주수량과 단가로 자동 계산.
  • ⑧ 합계 — 라인별 발주수량/단가/공급가/부가세/합계의 총합. 예시: 발주수량 140 / 공급가 90,000 / 부가세 9,000 / 합계 99,000.

[저장] 클릭 시 발주서가 ‘작성중’ 상태로 목록에 추가됩니다. 이후 [결재상신]으로 승인 받고, [발송]으로 거래처에 PDF/메일을 보냅니다.

전체 등록 절차 요약

  1. 발주서 목록에서 [구매요청서 불러오기] 클릭
  2. 구매요청정보에서 발주로 만들 PR 체크 → 하단 ‘품목별 발주수량 입력’에서 발주수량 입력
  3. [발주하기] → 발주서 등록 팝업 자동 오픈
  4. 거래처 선택 → 결제조건·인도조건 확인 → 비고 입력
  5. [저장] → 발주서 ‘작성중’ 등록
  6. 목록에서 발주서 선택 → [결재상신] → 승인 완료 후 [발송]으로 거래처에 송부

기타 기능

  • 마감 — 더 이상 진행하지 않을 발주서를 종결. 입고·송장 단계의 후보에서 제외
  • 복사 — 기존 발주서를 그대로 복제해 새 번호로 등록 (정기 발주에 유용)
  • 출력 / 다운로드 — 발주서 1건 PDF 출력 / 목록 엑셀 다운로드
  • 발송 — 등록된 거래처 메일로 발주서 PDF 송부. 발송 이력은 [발송내역]에서 확인
  • 결재상신 — 발주서를 전자결재로 올려 승인 받기. 사내 결재 정책에 따라 사전 결재가 필수일 수 있음

3.2. 발주대비 입고내역

개요

발주서(PO)별로 발주수량 대비 실제 입고된 수량·양품·불량·미입고 현황을 한 화면에서 확인하는 조회 전용 화면입니다. 발주가 정상적으로 입고됐는지 점검하고, 부분 입고/미입고 건을 빠르게 추려낼 때 사용합니다.

🧮 계산 규칙 — 발주수량(PO) − 입고수량(GR) = 미입고량. 입고수량 안에서 양품수량 + 불량수량의 합이 다시 입고수량이 됩니다.

화면 진입

좌측 사이드바 [구매관리] ▸ [구매오더(PO)] ▸ [발주대비 입고내역]

목록 화면

기본 조회 조건은 ‘발주일자 기준 당월 1일~오늘’입니다. 한 행이 발주 라인 1건이고, 같은 발주서 안에 여러 라인이 있으면 [소계] 행이, 화면 전체 끝에는 [합계] 행이 자동으로 표시됩니다.

발주대비 입고내역 — 5월 조회 결과(4건). 발주정보 + 입고정보를 한 행에 함께 표시

  • ① 검색 조건 — 발주일자 / 기간 / 거래처 전체 / 검색 조건 + [미입고 내역만 보기] 토글 + [조회] / [초기화]. 기준일을 ‘발주일자/입고일자/납기일자’로 바꿔서 다른 관점으로 조회할 수 있습니다.
  • ② [다운로드] — 현재 조회 결과를 엑셀로 내려받기.
  • ③ 발주정보 그룹 — 발주번호 / 발주일자 / 거래처코드 / 거래처명 / 납기일자 / 품목코드 / 품목명 / 품목유형 / 발주수량
  • ④ 입고정보 그룹 — 입고번호 / 입고일자 / 입고수량 / 양품수량 / 불량수량 / 미입고량. 입고가 여러 번 나눠 들어오면 같은 발주 라인이 입고건 수만큼 행이 늘어나고 ‘소계’로 합산됩니다.
  • ⑤ [소계] / [합계] 행 — 같은 발주서 안의 모든 라인 합계와 화면 전체 합계가 자동 계산됩니다. (예시: 합계 발주수량 420 / 입고 340 / 양품 320 / 불량 20 / 미입고 100)

• PO2605100002 / 5-10 / 공급사A / RM-A01 캔버스 원단 60 발주 → 60 입고 (양품 60·불량 0)
• PO2605100001 / 5-01 / 공급사A / RM-A01 캔버스 원단 60 발주 → 60 입고 (양품 60·불량 0)
• PO2605060001 / 5-06 / 공급사A / RM-A02 면 손잡이 끈 200 발주 → 120 입고 (양품 100·불량 20·미입고 100)
• PO2605060002 / 5-06 / 공급사B / RM-A03 실크 프린트 잉크 100 발주 → 100 입고 (양품 100·불량 0)

개요

공급사가 청구한 송장(Invoice Receipt, IR)을 등록하고, 구매오더(PO)·구매입고(GR)·송장(IR) 3건의 수량/단가/세액을 매칭해 매입채무 전표를 끊는 화면입니다. 송장확정 시 AP 전표가 자동 발행되며, GR/IR 단가차이가 있으면 PPV(구매가격차이)가 함께 인식됩니다.

📝 두 가지 입력 방식 — ① 일반송장: 이미 입고된 GR을 골라 청구 (정상 순서) / ② 선 송장: GR 전에 PO 기반으로 먼저 청구 (선청구). 일반송장이 표준이고, 선 송장은 입고 전 청구가 필요한 예외 케이스에서 사용합니다.

화면 진입

좌측 사이드바 [구매관리] ▸ [송장접수(IR)] ▸ [송장입력]

목록 화면

송장입력 목록 — 상단 송장 헤더 그리드, 하단 선택 송장의 상세품목정보

  • ① 기능 버튼 — [마감] / [일반송장-구매입고(GR)로 입력] / [선송장-구매오더(PO)로 입력] / [수정] / [삭제] / [송장확정] / [송장취소] / [출력] / [다운로드]. 신규 송장은 두 입력 버튼 중 하나로 시작합니다.
  • ② 송장 그리드 — 한 행이 송장 1건. 송장번호 / 송장일자 / 공급사송장번호 / 거래처코드 / 거래처명 / 통화코드 / 적용환율 / 총 공급가 / 총 부가세 / 총 합계금액 / 과세구분 / 결제조건 / 지급기한 / 발주서(PO)번호 등.
  • ③ 상세품목정보 — 상단에서 선택한 송장의 라인. 품목코드 / 품목명 / 규격 / 단위 / 송장수량 / 단가 / 공급가 / 부가세 / 합계 / 공장 / 창고 / 요청납기일자 / 발주항목번호.

송장입력 ① 일반송장 — 구매입고(GR)로 입력

상단 [일반송장-구매입고(GR)로 입력] 클릭 → 팝업이 열립니다. 이미 입고된 GR을 선택해 청구하는 정상 케이스입니다.

일반송장 팝업 — GR2605260001 선택, 송장수량 10,000 입력 후 Enter → 공급가/부가세 자동 계산

  • ① 검색 조건 — 입고일자 기간 / 거래처 / 부서 / 사원. 기본은 ‘입고일자 당월 1일~오늘’.
  • ② 구매입고(GR) 정보 그리드 — 청구 대상 GR을 체크. 한 송장에 동일 거래처의 GR만 묶을 수 있습니다 (다른 거래처 GR이 섞이면 ‘동일 거래처의 입고 내역만 일괄 처리가 가능합니다’ 알림).
  • ③ 송장상세정보 입력 — 송장 헤더에 해당. 송장일자 / 공급사송장번호* / 결제조건 / 지급기한 / 과세구분 / 외화거래 / 통화정보 / 비고. 공급사송장번호는 거래처가 보낸 원문 송장번호를 그대로 입력합니다.
  • ④ 라인 그리드 — 선택한 GR의 미청구 양품수량이 자동으로 펼쳐집니다. 입고수량 / 불량수량 / 양품수량 / 기청구수량 / 미청구수량 / 송장수량* / 잔여수량 / 단가* / 공급가 / 부가세 / 합계. 송장수량 입력 후 Enter를 치면 잔여수량이 계산되고, 단가 입력 후 Enter를 치면 공급가·부가세·합계가 자동 계산됩니다.
  • ⑤ [송장입력] — 입력된 헤더·라인으로 IR 1건을 생성합니다.

⌨️ Enter 입력이 핵심 — 송장수량/단가 셀 입력 후 반드시 Enter 키를 눌러야 잔여수량·공급가·부가세 자동 계산 로직이 실행됩니다.

송장입력 ② 선 송장 — 구매오더(PO)로 입력

상단 [선송장-구매오더(PO)로 입력] 클릭 → 팝업이 열립니다. GR보다 송장이 먼저 도착한 경우(선청구) 또는 GR 없이 청구해야 하는 예외 케이스에서 사용합니다.

선 송장 팝업 — PO2605060002 선택, 송장수량 10,000 입력 후 Enter → 공급가/부가세 자동 계산

  • ① 검색 조건 — 상태(전체/대기/처리중 등) / 발주일자 기간 / 거래처 / 부서 / 사원.
  • ② 구매오더(발주) 선택 — 청구 대상 PO를 라디오로 1건 선택. 한 송장에는 1개 PO만 매칭됩니다.
  • ③ 송장상세정보 입력 — 일반송장과 동일 (송장일자 / 공급사송장번호 / 결제조건 / 지급기한 / 과세구분 / 비고).
  • ④ 라인 그리드 — 선택 PO의 모든 라인이 펼쳐집니다. 발주수량 / 송장수량* / 잔여수량 / 단가* / 공급가 / 부가세 / 합계. 입력 방식은 일반송장과 동일.
  • ⑤ [송장입력] — 선 송장(NoGR 상태)으로 IR 1건이 생성됩니다. 추후 GR이 처리되면 매칭상태가 자동 재계산됩니다.

⚠️ 선 송장의 매칭 상태 — 등록 시점에는 GR이 없으므로 매칭상태 = NoGR. 입고(GR) 처리되면 시스템이 자동으로 Matched / Short / Over 등으로 재산정합니다. 단, NoGR 상태에서는 송장확정이 차단됩니다 — 반드시 GR 처리 후 확정하세요.

송장확정 — AP전표 발행 + PPV 인식

목록에서 송장 행을 체크하고 상단 [송장확정] 클릭 → 확인 alert가 뜹니다. [확인]을 누르면 매입채무 전표(AP)가 자동 생성됩니다.

송장확정 alert — GR/IR 단가차이가 있으면 PPV(구매가격차이)로 함께 전표처리됨을 안내

  • 일치(Matched) — PO·GR·IR 수량/단가/세액 모두 일치.
  • 부분청구(Short) — IR 수량이 미청구 양품수량보다 적음. 잔량은 차기 송장에서 청구.
  • 과다청구(Over) — IR 수량이 미청구 양품수량을 초과. 확정 차단 (추가 GR 처리 또는 송장 수정 필요).
  • 단가상이(PriceDiff) — PO 단가 ≠ IR 단가. 확정 시 차액이 PPV(구매가격차이) 계정으로 자동 인식됩니다. (위 alert가 PriceDiff 상태일 때 표시됩니다.)
  • 세액차이(TaxDiff) — 세금코드/세율 불일치. 확정 차단.
  • GR없음(NoGR) — 선 송장 상태이거나 참조 GR 누락. 확정 차단 (GR 처리 후 재확정).

📒 회계 분개(GR · 검수 · 반품 · IR · PPV · 마감) 전체 흐름은 별도 페이지 5.2. 구매관리 회계처리에 정리되어 있습니다.

입력 절차 요약 — 일반송장 (정상 케이스)

  1. [일반송장-구매입고(GR)로 입력] 클릭
  2. 청구 대상 GR 체크 (동일 거래처만 가능)
  3. 송장일자 / 공급사송장번호 / 결제조건 / 지급기한 / 과세구분 입력
  4. 라인별 송장수량 입력 → Enter → 잔여수량 계산 확인
  5. 단가 입력 (PO 단가 기본 세팅됨, 송장 단가가 다르면 수정) → Enter → 공급가/부가세/합계 자동 계산
  6. [송장입력] → IR 신규 등록
  7. 목록에서 송장 체크 → [송장확정] → 확인 alert에서 [확인] → AP 전표 자동 발행 (+ 단가차이 시 PPV 인식)

기타 기능

  • 송장취소 — Approved 상태의 IR을 역분개(Cancelled)로 처리. 대금지급(Paid) 전에만 가능.
  • 수정 — Draft 상태에서만 헤더/라인 수정 가능. Approved 후에는 수정 불가, 취소 후 재작성.
  • 삭제 — Draft 상태에서만 가능.
  • 마감 — 추가 송장이 없을 것으로 확정된 PO/GR을 종결.
  • 출력 / 다운로드 — 송장 1건 PDF / 목록 엑셀.

5.2. 구매관리 회계처리

5.2. 구매관리 회계처리

📒 이 문서는 구매 사이클의 회계 분개를 한 곳에 모았습니다. 실제 화면 사용법은 [4.1 구매입고서] / [4.2 검수 및 반품처리] / [5.1 송장입력] 각 페이지를 참조하세요.

개요

GR(입고) → 검수(양품/불량) → 반품 → IR(송장확정) → 월마감 → 기말마감(PPV 배부)에서 회계처리가 어떤 방식으로 처리되는 정리한 문서입니다. 핵심 가교 계정은 GR/IR 임시계정(00001) — GR과 IR의 시점 차이를 메우는 조정계정으로, 매칭이 끝나면 잔액이 0이 됩니다.

📒 실제 사용 계정코드 — GR/IR 임시계정(00001) · 원재료(15300) · 원재료-검수대기(15301) · 원재료-반품대기(15302) · 부가세대급금(13500) · 선급금(13100) · 외상매입금(25100) · 미지급금-GRIR미정산(25302) · PPV 구매가격차이(00004) · 제품매출원가(45500) · 상품매출원가(45100) · 재공품 WIP(16900) · 제품(15000)

Part A. GR 입고 · 검수 · 반품 (실시간)

GR 시점에는 세금계산서가 아직 없으므로 부가세를 인식하지 않고, PO 단가 × 입고수량으로 GR/IR 임시계정에 잠정 인식합니다. 검수에서 양품/불량을 가르고, 불량은 반품 출고 시점에 GR/IR 임시계정을 같이 소멸시킵니다.

【T1】 GR 입고 — 검수대기 + GR/IR 임시계정 인식

트리거: 구매입고서 등록 → 전표일자 = GR 입고일자 / 헤더거래처 O / 전표경로 = 구매입고(GR)

예시: PO단가 10,000 × 100개 = 1,000,000 (VAT 없음 — 세금계산서 미수취)

구분 계정과목 금액 적요
차변 원재료-검수대기(15301) 1,000,000 원재료검수대기_PO번호-항목_GR번호-항목
대변 GR/IR 임시계정(00001) 1,000,000 GRIR정리_PO번호-항목_GR번호-항목

⚠️ 재고테이블에는 원재료(15300)로 입고 처리되지만, 회계 분개는 검수대기(15301)로 구분 인식합니다. 해당월 입고건은 해당월 마감 전에 반드시 검수 완료해야 합니다 (검수대기 잔액 존재 시 마감 차단).

【T2】 검수 확정 — 양품 → 정상재고

트리거: 검수 완료 → 양품 판정 / 전표일자 = GR 입고일자 (자동) / 전표경로 = 구매검수

예시: 양품 70개 × 10,000 = 700,000 (계정 대체만 발생, 재고테이블 변동 없음)

구분 계정과목 금액 적요
차변 원재료(15300) 700,000 원재료_..._양품확정
대변 원재료-검수대기(15301) 700,000 원재료검수대기_..._양품확정

【T3】 검수 확정 — 불량 → 반품대기

트리거: 검수 완료 → 불량 판정 / 전표일자 = GR 입고일자 (자동) / 전표경로 = 구매검수

예시: 불량 30개 × 10,000 = 300,000 (계정 대체만 발생, 재고테이블 변동 없음)

구분 계정과목 금액 적요
차변 원재료-반품대기(15302) 300,000 원재료반품대기_..._불량확정
대변 원재료-검수대기(15301) 300,000 원재료검수대기_..._불량확정

【T4】 반품 처리 — GR/IR 임시채무 소멸

트리거: 반품요청 → 입출고요청서 → 출고처리 / 전표일자 = 출고처리일 / 전표경로 = 입출고요청

예시: 불량 30개 전량 반품 → 재고 차감 + 분개 동시 발생

구분 계정과목 금액 적요
차변 GR/IR 임시계정(00001) 300,000 GRIR정리_..._반품
대변 원재료-반품대기(15302) 300,000 원재료반품대기_..._반품출고

→ GR/IR 임시계정 잔액 = 양품 700,000만 남음 (반품 300,000 소멸). 이 잔액이 IR 송장확정 시 상계 대상이 됩니다.

Part B. 송장확정(IR) — 매입채무 인식

공급사 세금계산서를 수취하면 GR/IR 임시계정을 상계하고 외상매입금(25100)을 확정합니다. PO 단가와 IR 단가가 다르면 차액을 PPV(구매가격차이)로 분리 인식합니다. (

매칭상태별 처리 — Matched/Short → 정상 전표, Over/TaxDiff/NoGR → 확정 차단, PriceDiff → 사용자 컨펌 후 허용

【T5】 정상 IR 확정 — Matched, VAT 없음 (영세율·면세 거래 등)

트리거: 송장확정 / 전표일자 = 송장일자(세금계산서 발행일) / 헤더거래처 O / 전표경로 = 구매송장

예시: 양품 70개 × @10,000 = 700,000

구분 계정과목 금액 적요
차변 GR/IR 임시계정(00001) 700,000 GRIR정리_..._IR번호_송장확정
대변 외상매입금(25100) 700,000 외상매입금_..._IR번호_송장확정

【T6】 정상 IR 확정 — Matched, VAT 10% 포함

예시: 공급가 700,000 + VAT 70,000 = 외상매입금 770,000

구분 계정과목 금액 적요
차변 GR/IR 임시계정(00001) 700,000 GRIR정리_..._IR번호_송장확정
차변 부가세대급금(13500) 70,000 부가세대급금_IR번호_매입세액
대변 외상매입금(25100) 770,000 외상매입금_..._IR번호_송장확정

🧾 VAT는 IR(세금계산서 수취) 시점에만 인식 — GR 시점에는 세금계산서가 없으므로 부가세 인식 불가. 부가세 신고는 외상매입금(25100) 잔액 = 세금계산서 합계로 대사합니다.

예시: PO 10,000 / IR 10,200 / 100개 → 공급가 1,020,000 / VAT 102,000 / 외상매입금 1,122,000 / PPV 불리 20,000 (비용 증가)

⚖️ 불리 vs 유리 핵심 — IR 단가 > PO 단가면 PPV 차변(불리), IR 단가 < PO 단가면 PPV 대변(유리). 송장확정 alert의 “GR/IR 단가차이 상태는 PPV로 확정처리 및 전표처리가 진행됩니다”가 이 분개를 가리킵니다. 재고는 PO 단가(표준) 기준으로 유지되고, 단가차이만 PPV 계정으로 분리됩니다.

Part C. 송장 월마감 — GR/IR 재분류 + 차월 역분개

월말 시점에 GR/IR 임시계정에 잔액이 남아있으면(GR은 끝났는데 IR 미도착, 또는 그 반대), 재무상태표(BS) 표시를 위해 거래처별 정규계정으로 재분류합니다. 차월 1일에 시스템이 자동으로 역분개해 GR/IR 임시계정을 원복합니다.

Part D. 기말마감 — PPV 배부 (총량비율안분)

기말(월말 또는 분기말)에 PPV(구매가격차이) 잔액을 재고/매출원가에 배부해 PPV 계정 잔액을 0으로 만듭니다. 앵커는 총량비율안분 방식 — 기초재고 + 당월입고 총량을 4개 위치(원재료 잔량 / 재공품 투입분 / 완성품 미판매 / 매출원가)로 분해하고, 위치별 수량 비율로 PPV를 안분합니다.

배부 로직

기초재고 + 당월입고 총량을 4개 위치(① 원재료 잔량 / ② 재공품 투입분 / ③ 완성품 미판매 / ④ 매출원가)로 분해하고, 위치별 수량 비율로 PPV 안분.

예시: 기초 200 + 입고 100 = 총 300개, PPV 불리 20,000원

  • 2. 생산마감 — 생산실적/원가 A+ 확정 (PPV 안분의 ④ 매출원가 수량 확정)
  • 3. 재고실사 → 재고마감 — ① 원재료 / ③ 완성품 기말수량 확정, 생산투입수량확정 → ② 재공품 수량 확정

6.2. GR/IR 잔액조회

개요

GR/IR 임시계정(00001)의 미정산 잔액을 라인별로 보여주는 보고서입니다. GR과 IR의 시점·금액 차이로 발생하는 잔액을 GRNI(Goods Receipt Not Invoiced) / IRNI(Invoice Receipt Not Received) 두 방향으로 분리해서 표시합니다.

⏰ GR/IR 임시계정 잔액은 최종 0이 되어야 정상입니다. 잔액이 누적되면 월마감 시 거래처별로 미지급금-GRIR미정산(25302) 또는 선급금(13100)으로 재분류되고, 차월 1일에 자동 역분개됩니다. 90일 초과 시 대표이사 보고 대상.

핵심 정의

  • GRNI (Goods Receipt Not Invoiced) — 입고는 됐는데 송장이 아직 안 옴. 양품금액 > 송장금액. 채권자 입장에서 잠재 부채.
  • IRNI (Invoice Receipt Not Received) — 송장은 받았는데 입고가 안 됨 / 부족 입고. 송장금액 > 양품금액. 비정상 상태 (선급 또는 입고 누락).
  • 미정산 잔액 = 양품금액 − 송장금액. 양수면 GRNI, 음수면 IRNI.
  • 기준일자 — 일반적으로 입고일. 입고일이 없으면 송장일을 기준일로 사용.
  • 경과일수 = 현재일자(또는 리포트 실행일) − 기준일자.

개요

구매오더(PO) 라인 기준으로 매핑된 모든 GR과 IR의 수량/금액을 합산해 진행률을 보여주는 보고서입니다. ‘이 PO는 발주 100개 중 입고 80개, 송장 70개 → 미입고 20개, 미청구 10개 + 납기 7일 지연’ 같은 PO 단위 진척도를 한 화면에서 확인할 수 있습니다.

🧭 이 보고서는 구매 운영의 ‘게이트웨이 대시보드’입니다. PO별로 문제가 보이면 [6.1 GR/IR 불일치 조회] 또는 [6.2 GR/IR 잔액조회]로 드릴다운해 원인을 파악합니다.

핵심 계산식

지표 계산식 활용
양품금액 PO단가 × 양품수량 기대 송장금액
송장금액 PO단가 × 송장수량 현재 청구된 금액
미입고잔량 발주수량 − 송장수량 공급사가 더 청구할 잔여
미청구잔량 양품수량 − 송장수량 당사가 송장 받아야 할 잔여 (GRNI 후보)
납기경과일수 최종입고일 − 납기일자 (입고없으면 System Date − 납기) 지연도 점검
납기지연수량 납기 초과 시점의 미입고 수량 지연 충격도

활용 시나리오

  1. 주간 — 미입고잔량 > 0 + 납기경과일수 > 0 PO를 필터링 → 공급사 납기 독촉.
  2. 월간 — 미청구잔량 > 0인 PO를 식별 → 공급사에 송장 청구 요청 (GRNI 사전 예방).
  3. 문제 발견 시 — 해당 PO 라인을 [6.1] (매칭 차이 확인) 또는 [6.2] (계정 잔액 확인)로 드릴다운.
  4. PO 마감 — 발주수량 = 송장수량 + 미청구잔량 = 0인 PO는 [발주서] 화면에서 마감 처리.
